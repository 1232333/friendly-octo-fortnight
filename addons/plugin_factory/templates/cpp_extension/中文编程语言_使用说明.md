# 中文游戏编程语言使用说明

## 当前版本状态

当前仓库中的旧原型仍然是“中文源码 → GDScript”的转译实现。它能验证编辑器接入和部分中文语法，但不是项目最终目标，也不应被描述为独立编译语言。

项目正在转向原生编译器与独立字节码虚拟机：
中文源码(.zh) → AST/语义分析 → 自有字节码(.zhbc) → 中文 VM → Godot Host API

## 正式版本的运行方式（目标）

1. 在中文语言编辑器中编写 .zh 源码。
2. 编译器生成独立的 .zhbc 文件。
3. 字节码验证器检查文件版本、指令和类型/寄存器边界。
4. 中文 VM 加载并执行字节码。
5. VM 通过 Godot Host API 控制节点、输入、信号、物理和 UI。
6. 输出、错误、调用栈和变量监视由 VM 调试接口提供。

## 验收原则

- 不生成 GDScript 作为用户程序。
- 编译器和 VM 必须有不依赖 Godot 的 C++ 单元测试。
- 编译产物必须是自有字节码格式。
- 相同字节码在独立测试运行器与 Godot 插件中执行结果一致。
- 未完成 VM 的功能不得在 UI 中标记为已支持。

## 原生事件入口（正在验证）

编译器支持将生命周期事件编译为独立的 ZHBC 函数入口：

```text
当 游戏开始:
    打印("游戏开始")
结束

当 每帧(delta):
    打印(delta)
结束
```

在 Godot 场景中添加原生 `ChineseProgram` 节点，并在检查器的 `bytecode_path` 属性中指定已编译的 `.zhbc` 文件。节点的 C++ `_ready` 回调调度 `游戏开始`，C++ `_process(delta)` 回调调度 `每帧(delta)`。事件入口在 VM 中执行，不生成 GDScript。此功能仍需完成 GDExtension 构建与 Android ARM64 真机验证。

## 当前已实现的 Godot Host API（第二阶段开发中）

中文 VM 通过原生 HostCall 指令调用宿主函数，不会把调用翻译成 GDScript。当前接入的节点接口：

- `获取节点("UI/按钮")`：从本次运行传入的场景根节点查找 Node，返回 VM 节点句柄。
- `设置可见(节点, 假)`：设置 CanvasItem 的可见状态。
- `设置位置(节点, x, y)`：设置 Node2D 或 Control 的二维位置。
- `设置属性(节点, "属性名", 值)`：设置 Godot 对象的标量属性。
- `读取属性(节点, "属性名")`：读取布尔、整数、浮点或字符串属性。

示例：

```text
变量 按钮 = 获取节点("UI/按钮")
设置可见(按钮, 真)
设置位置(按钮, 320, 180)
设置属性(按钮, "text", "开始游戏")
打印("按钮已设置")
```

节点句柄只在一次同步 VM 执行期间有效；不可保存到字节码文件或跨场景生命周期复用。当前 API 不覆盖对象生命周期托管、信号连接、异步调用或完整 Variant 类型。
