# 中文游戏编程语言设计（原生编译器 / VM 版）

> 本文定义项目的正式目标架构。旧版“中文源码转 GDScript”仅是临时原型，不是最终语言实现；新功能不得继续把 GDScript 当作编译目标。

## 1. 产品定义

开发一门具有自己语言规范、编译器、字节码格式、虚拟机、标准库和调试信息的中文编程语言。中文是语言本身的语法与标识符，不是给另一门语言换关键字。

正式执行链：

源文件(.zh) → UTF-8 Lexer → Parser → AST → 语义分析/类型检查 → Bytecode Generator → 字节码(.zhbc) → 中文 VM → Godot Host API

关键约束：
- 编译器不得生成 GDScript、C# 或其他宿主语言源码。
- VM 直接执行项目定义的字节码；Godot 只提供引擎宿主能力。
- 同一份字节码应可在编辑器运行、游戏运行和自动化测试中执行。
- 编译阶段与运行阶段分离：可先编译成 .zhbc，再由 VM 加载运行。
- 错误信息使用中文，并携带源文件、行、列和调用栈位置。

## 2. 编译器分层

1. Lexer：按 UTF-8 解码，识别中文/ASCII 标识符、数字、字符串、注释、运算符和关键字；错误定位按 Unicode 字符列计数。
2. Parser：生成 AST，不允许用逐行字符串替换代替语法分析。
3. 语义分析：作用域、变量声明、函数声明、类型推导/检查、返回路径、未定义标识符、参数数量检查。
4. IR：生成与 Godot 无关的控制流中间表示，基本块和跳转显式化。
5. Bytecode Generator：生成带版本号的指令流、常量池、函数表、源位置表。
6. Verifier：加载前验证指令边界、常量索引、寄存器/栈深度、跳转目标、函数签名和字节码版本。

## 3. 字节码与 VM

第一版采用寄存器式字节码，减少栈式表达式实现复杂度。每个函数包含寄存器数量、参数数量、指令区间和源位置映射。

首批指令类别：
- 常量/数据：LOAD_CONST、MOVE、LOAD_NULL
- 变量：LOAD_LOCAL、STORE_LOCAL、LOAD_GLOBAL、STORE_GLOBAL
- 算术：ADD、SUB、MUL、DIV、MOD、NEG
- 比较/逻辑：EQ、NE、LT、LE、GT、GE、NOT
- 控制流：JUMP、JUMP_IF_FALSE、CALL、RETURN
- 宿主调用：HOST_CALL
- 输出/调试：标准库输出函数、断点和源位置标记

VM 负责值表示、调用帧、局部变量、全局变量、执行预算、异常传播和调试状态。首版可用 C++ tagged value（空、布尔、整数、浮点、字符串、对象句柄）实现；后续再增加垃圾回收与闭包。

## 4. Godot 集成边界

Godot 通过 GDExtension 注册一个原生语言服务对象，不把用户脚本变成 GDScript：
- 编译(源码) → 编译结果/字节码
- 加载(字节码)
- 运行(模块, 参数)
- 暂停/继续/停止
- 读取变量/调用栈/源位置

VM 的 Host API 通过受控接口访问场景树、节点属性、输入、信号、计时器、物理、动画、资源和 UI。VM 不直接依赖 Godot 内部私有实现；所有引擎调用经过 Host API 注册表，支持参数/返回值类型校验。

生命周期由节点上的语言脚本资源/组件驱动：
- 当 游戏开始:
- 当 每帧(delta):
- 当 物理帧(delta):
- 当 输入事件(事件):
- 当 退出场景:

这些事件编译为 VM 函数表中的入口，不映射成 GDScript 方法。

## 5. 第一阶段可验收垂直切片

先完成一条真正的原生编译执行闭环，不急着铺大量 API：

    变量 分数: 整数 = 80
    打印("分数：", 分数)
    如果 分数 >= 60:
        打印("及格")
    否则:
        打印("不及格")
    结束

验收要求：
1. 编译产物是项目自有的 .zhbc 字节码，不含生成的 GDScript。
2. VM 独立执行字节码并产生标准输出。
3. 单元测试直接调用 Lexer/Parser/Compiler/VM，不启动 Godot 也能验证输出。
4. Godot GDExtension 只负责加载字节码、调用 VM 和转发 Host API。
5. 在 Godot 输出面板显示 VM 的输出；同一字节码在命令行测试与 Godot 中结果一致。
6. 错误测试覆盖非法字符、未声明变量、类型错误、除零和无效跳转。

## 6. 里程碑

- M0 架构冻结：明确语言规范、字节码版本、VM/Host API 边界；停止增加 GDScript 转译功能。
- M1 语言核心：Lexer、AST Parser、语义分析、表达式和变量。
- M2 原生字节码：IR、字节码生成、序列化/反序列化、Verifier。
- M3 VM：算术、比较、分支、循环、函数、输出、错误栈。
- M4 Godot Host API：打印、节点句柄、属性读写、生命周期事件。
- M5 工具链：编辑器面板、编译缓存、断点、变量监视、热重载。
- M6 完整语言：模块、类型系统增强、容器、闭包、协程、资源和 UI API。

## 7. 当前状态声明

仓库旧版实现仍是 C++ 行级解析后生成 GDScript 的 MVP，尚不是真正的独立编译语言。不能把旧版的“编译成功”或 GDScript 解析成功当成新架构验收。新架构必须以 .zhbc + VM 执行测试为准。
